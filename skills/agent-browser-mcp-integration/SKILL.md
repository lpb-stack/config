# Agent-Browser MCP Integration

## Resource Locations

All support files live at `/opt/pi-support` (set by `PI_SUPPORT_DIR` env var).

| Path | Purpose |
|------|---------|
| `$PI_SUPPORT_DIR/session-uuid.ts` | Generate unique session IDs |
| `$PI_SUPPORT_DIR/browser-state-cleanup.py` | Cleanup browser state volumes |
| `$PI_SUPPORT_DIR/config/` | Prompt templates, action policies |
| `$PI_SUPPORT_DIR/schemas/` | JSON validation schemas |
| `$PI_SUPPORT_DIR/docs/` | Documentation |

To inspect or edit: `cat /opt/pi-support/schemas/browser-validation-schema.json`
To customize: copy to workspace and edit the local copy.

## When to Use

When you need browser automation — navigation, element interaction, screenshots, and visual analysis. Use when the user asks to "navigate to a URL", "click an element", "fill a form", "take a screenshot and analyze it", or "test a user flow".

## Architecture

```
agent-browser MCP (primary: navigation, refs, clicks, screenshots)
chrome-devtools-mcp (diagnostics only, disabled by default)
Local vision model (Lemonade server — endpoint + model from `lpb-config show`)
```

## Prerequisites

```bash
# Verify agent-browser is installed
agent-browser --help

# Chrome must be available (bundled via `agent-browser install` or via CDP on 9272)
# Chrome DevTools MCP is disabled by default; enable with:
# export CHROME_DEVTOOLS_ENABLED=true
```

## Core Workflow

### 1. Navigate to a URL

```bash
agent-browser open https://example.com
```

### 2. Get Compact Element Refs (Accessibility Tree)

```bash
agent-browser snapshot -i
```

Returns interactive elements with compact refs (200-400 tokens vs 3000-5000 DOM):
```
heading "Example Domain" [ref=e1]
paragraph "This domain is for use in illustrative examples..." [ref=e2]
link "More information..." [ref=e3]
```

### 3. Generate Annotated Screenshot

```bash
agent-browser screenshot --annotate /tmp/annotated.png
```

Produces numbered bounding boxes [1], [2], [3] that correspond to refs @e1, @e2, @e3.

### 4. Analyze with Local Vision Model

Resolve the live endpoint and model first — never hardcode them:
`lpb-config show` prints the Lemonade server URL and the default model
(use those as `LEMONADE_BASE_URL` / `VISION_MODEL` below).

```bash
SS_BASE64=$(base64 -w 0 /tmp/annotated.png)
curl -s "$LEMONADE_BASE_URL/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"$VISION_MODEL\",
    \"messages\": [
      {
        \"role\": \"user\",
        \"content\": [
          {\"type\": \"text\", \"text\": \"Describe the layout. Map numbered labels [1], [2], [3] to element types (heading, link, button). Identify which element is the primary CTA.\"},
          {\"type\": \"image_url\", \"image_url\": {\"url\": \"data:image/png;base64,$SS_BASE64\"}}
        ]
      }
    ],
    \"max_tokens\": 1024,
    \"stream\": false
  }" | python3 -c "
import sys, json
data = json.load(sys.stdin)
msg = data['choices'][0]['message']
reasoning = msg.get('reasoning_content', '')
content = msg.get('content', '')
result = reasoning.strip() if reasoning.strip() else content.strip()
print(result)
"
```

### 5. Interact Using Refs

```bash
agent-browser click @e3
agent-browser type @e4 "search query"
agent-browser fill @e5 "username"
```

## Snapshot Filter Options

| Flag | Description |
|------|-------------|
| `-i` | Interactive elements only (default, recommended) |
| `-c` | Compact mode |
| `-d N` | Depth limit (e.g., `-d 3`) |

| `-u` | Include link URLs |

## Session Isolation

Each PI session gets an isolated browser state. Subagents get unique sessions:

```bash
# Default session (main agent): use PI_WORKTREE_ID
export AGENT_BROWSER_SESSION="${PI_WORKTREE_ID}"

# Subagent session: generate unique ID with test name
export AGENT_BROWSER_SESSION=$(session-uuid "${PI_WORKTREE_ID}-<test-name>")
# → pi-main-abc123-login-flow-7f3a9b2c

# Or via the session tool argument
agent-browser snapshot --session worktree-abc123-login-flow-7f3a9b2c
```

**Session naming convention:** `<worktree-id>-<test-name>-<uuid>`
- `worktree-id`: cross-worktree uniqueness (from `PI_WORKTREE_ID`)
- `test-name`: human-readable test identifier
- `uuid`: prevents collisions (generated by `session-uuid` — installed globally)

**Two flows:**
- **Flow A (Bundled Chrome — default):** Safe, isolated, for automated testing and subagents. Uses `AGENT_BROWSER_SESSION` and `AGENT_BROWSER_ALLOWED_DOMAINS`. Bundled Chrome is at `AGENT_BROWSER_EXECUTABLE_PATH=/home/dev/.local/share/agent-browser/chrome/chrome-linux64/chrome` (configured in `..env`).
- **Flow B (Host Chrome CDP — `--cdp 9222`):** Shared state, for live user collaboration. Does NOT use `AGENT_BROWSER_ALLOWED_DOMAINS` (conflicts with CDP). Override bundled Chrome with `agent-browser --cdp 9222 ...`.

State is auto-saved and restored with `--restore`:

```bash
agent-browser --restore open https://example.com
```

State files are stored in Docker volume `/browser-states/<session-id>/` with automatic housekeeping (cleanup after 7 days or 20 sessions).

Encrypt session data with:
```bash
export AGENT_BROWSER_ENCRYPTION_KEY="your-32-byte-aes-gcm-key-here"
```

## Security Settings

| Setting | Purpose | Default |
|---------|---------|---------|
| `AGENT_BROWSER_ALLOWED_DOMAINS` | Navigation allowlist (localhost auto-allowed) | `localhost,127.0.0.1` |
| `AGENT_BROWSER_MAX_OUTPUT` | Prevent context flooding | 4000 |
| `AGENT_BROWSER_CONTENT_BOUNDARIES` | LLM safety markers | false |
| `AGENT_BROWSER_IDLE_TIMEOUT_MS` | Daemon cleanup timeout | 300000 (5 min) |

Configure in `..env.browser`:
```bash
export AGENT_BROWSER_ALLOWED_DOMAINS="*.github.com"
```

## Tool Profiles (agent-browser MCP)

The MCP server uses `--tools` to control context size:

| Profile | Tools Included |
|---------|---------------|
| `core` | open, snapshot, click, screenshot, fill, type (default) |
| `network` | route interception, HAR export, request inspection |
| `tabs` | back/forward/reload, tab management, frames, dialogs |
| `state` | cookies, storage, auth, sessions |
| `react` | React tree, component inspect, renders, suspense, Web Vitals |
| `debug` | console, errors, trace, profiler, accessibility, diff |
| `mobile` | viewport, device emulation, geolocation, media queries |
| `all` | every tool (avoid — bloats context) |

**Configuration:** `agent-browser mcp --tools core,network,tabs,state,react,debug`

## When to Use agent-browser vs chrome-devtools-mcp

| Task | Use | Why |
|------|-----|-----|
| "Click the login button" | agent-browser snapshot + `click @ref` | Deterministic refs, ~200 tokens |
| "Fill the form" | agent-browser `type @ref "value"` | Precise element targeting |
| "What does this page look like?" | chrome-devtools-mcp screenshot → vision | Visual analysis |
| "Check for memory leaks" | chrome-devtools-mcp `take_heapsnapshot` | Diagnostics |
| "Profile page performance" | chrome-devtools-mcp `performance_start_trace` | Diagnostics |
| "Test a user flow" | agent-browser + MCP screenshot | Interaction + visual verification |

## Heavy Page Handling

For pages with videos, animations, or heavy media:

```bash
# Option 1: Block via agent-browser network routes
agent-browser route "block" "**/*youtube.com/embed/*" "**/*.mp4"

# Option 2: Strip media elements before screenshot
agent-browser eval "document.querySelectorAll('iframe,video,source,picture,canvas,svg').forEach(el => el.remove());"
agent-browser screenshot /tmp/clean.png

# Option 3: Use low-quality JPEG
agent-browser screenshot --annotate --screenshot-format jpeg --screenshot-quality 50 /tmp/compressed.png
```

## Chrome DevTools MCP (Diagnostics)

Disabled by default. Enable for memory/performance/Lighthouse diagnostics:

```bash
export CHROME_DEVTOOLS_ENABLED=true
```

Available tools:
- `take_heapsnapshot` — memory leak investigation
- `performance_start_trace` / `performance_stop_trace` — performance profiling
- `analyze_insight` — performance insights
- `lighthouse_audit` — SEO/accessibility/best-practices scoring
- `screencast_start` / `screencast_stop` — live viewport streaming

## Accessibility (axe-core)

Run axe-core accessibility audits directly via agent-browser:

```bash
# Run full axe-core audit on current page
agent-browser a11y
# → violations, incomplete, passes count with details

# With JSON output
agent-browser a11y --json

# Filter by tags (e.g., only WCAG A and AA)
agent-browser a11y --tags "WCAG 2.1 A,WCAG 2.1 AA"

# Scope to specific element
agent-browser a11y --selector "#main-content"
```

## Web Vitals

Measure Core Web Vitals on the current page:

```bash
agent-browser vitals
# → ttfb, fcp, lcp, cls, inp, hydration summary

# With JSON output
agent-browser vitals --json

# Measure on navigation
agent-browser vitals https://example.com
```

## Batch Execution

For **simple commands without flags**, use the batch command:

```bash
agent-browser batch "open https://example.com" "snapshot -i"
```

For **complex commands with flags** (e.g., `--annotate`), chain commands instead — the batch parser has issues with CLI flags:

```bash
# Recommended: chain commands (browser persists via daemon)
agent-browser open https://example.com && agent-browser snapshot -i && agent-browser screenshot --annotate /tmp/ss.png
```

Or use JSON stdin mode for batch:

```bash
echo '["open","https://example.com","snapshot","-i","screenshot"]' | agent-browser batch --json
```

## Pitfalls

- **Chrome must be running on port 9222** for chrome-devtools-mcp (agent-browser uses bundled Chrome by default)
- **Heavy pages crash/slow MCP**: Strip media elements before screenshotting
- **Large base64 payload**: Use JPEG quality 50-60 to keep under 500KB
- **Vision model truncated**: Use `max_tokens: 1024` minimum; retry with 2048 if truncated
- **Refs are session-scoped**: Never reuse refs across different `AGENT_BROWSER_SESSION` values
- **MCP context bloat**: Use tool profiles (`core,network` instead of `all`)
- **Batch command flags**: The `agent-browser batch` parser treats flags like `--annotate` as selectors. Use `&&` chaining for complex commands instead.

## Verification

- Snapshot output is 200-400 tokens (not 3000-5000 DOM)
- Annotated screenshot labels [1], [2], [3] match refs @e1, @e2, @e3
- Model response uses `reasoning_content` first, then `content` fallback
- `finish_reason` is `"stop"` (not `"length"`)
- Session isolation works: two sessions with different `AGENT_BROWSER_SESSION` don't interfere

## Subagent Orchestration

For spawning subagents with isolated browser sessions:

```bash
# 1. Generate unique session
SESSION_ID=$(session-uuid "${PI_WORKTREE_ID}-my-test")

# 2. Do work
agent-browser --session "$SESSION_ID" open https://example.com
agent-browser --session "$SESSION_ID" snapshot -i
agent-browser --session "$SESSION_ID" vitals --json

# 3. ALWAYS close the session to prevent zombie Chrome processes
agent-browser --session "$SESSION_ID" close
```

**Critical:** Always call `agent-browser --session <id> close` when done. Without it, Chrome renderer/GPU processes become zombies and fill the process table.
